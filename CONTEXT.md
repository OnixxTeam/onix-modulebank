# Course Action Runtime

Учебный контур ModuleDev: обобщённый C# runtime публикует зарегистрированные PostgreSQL-функции
как HTTP actions (неделя 1) и исполняет версионированные процессы поверх них (неделя 2). Ключевая
особенность контекста — ни одно предметное имя не зашито в C#: действия и карты процессов
публикуются данными и исполняются без пересборки.

## Language

### Action runtime

**Action**:
Опубликованная единица предметной работы: манифест плюс целевая PostgreSQL-функция, вызываемая
через общий маршрут.
_Avoid_: Endpoint, handler, команда

**Manifest**:
Запись каталога, объявляющая контракт action — schemas, outcomes, policy, целевую функцию.
_Avoid_: Definition, конфиг, метаданные

**Outcome**:
Объявленное предметное завершение вызова action в верхнем регистре. Не является статусом
транспорта и не является ошибкой.
_Avoid_: Status, result code, state

**Policy**:
Требуемое право в форме `scope:verb`, которое principal обязан иметь для вызова action.
_Avoid_: Permission, role, право доступа

**Principal**:
Субъект вызова, чьи scopes проверяются на стороне сервера. `workflow-worker` — принципал,
под которым воркер вызывает actions.
_Avoid_: User, client, актор

**Dispatch**:
Запись факта вызова action: кто, что, с каким результатом. Фиксируется в той же транзакции,
что и предметный эффект.
_Avoid_: Log, audit record, trace

### Определение процесса

**Flow**:
Именованный процесс. Стабильное имя, за которым стоит набор версий.
_Avoid_: Workflow, процесс, сценарий

**Flow version**:
Неизменяемая опубликованная версия карты. После публикации не меняется никогда.
_Avoid_: Revision, релиз, снапшот

**Map**:
Документ `course-1`, описывающий flow version: steps, transitions и tasks. Единица публикации.
_Avoid_: Definition file, схема процесса, BPMN

**Step**:
Узел карты одного из четырёх типов: `automatic`, `wait_signal`, `manual`, `end`.
_Avoid_: Node, stage, этап

**Route**:
Переход между шагами, выбираемый по конкретному outcome.
_Avoid_: Edge, branch, ветка

**Task**:
Закреплённый в шаге `automatic` контракт вызова action вместе с policy, timeout, retry и mapping.
_Avoid_: Job, действие, вызов

**Pinned version**:
Версия карты, к которой навсегда привязан уже запущенный процесс. Активация новой версии на него
не влияет.
_Avoid_: Current version, зафиксированная версия

**Active version**:
Единственная published-версия flow, выбираемая для новых процессов.
_Avoid_: Latest, текущая, default

### Исполнение

**Process**:
Экземпляр конкретной flow version с собственным состоянием и историей.
_Avoid_: Instance, run, execution

**Business key**:
Внешний ключ идемпотентности запуска: пара flow плюс business key даёт не более одного процесса.
_Avoid_: Correlation key, идентификатор заявки

**Job**:
Единица работы, порождаемая шагом `automatic` и подлежащая захвату воркером.
_Avoid_: Task, work item, очередь

**Attempt**:
Одна попытка исполнения job. Строки попыток только добавляются.
_Avoid_: Try, run, итерация

**Signal**:
Идемпотентно принятое внешнее событие, продвигающее процесс из шага `wait_signal`.
_Avoid_: Message, event, уведомление

**Event**:
Строка append-only истории процесса. История дополняется и никогда не переписывается.
_Avoid_: Log, audit, changelog

**Start data**:
Неизменяемый JSON, переданный `flow start --data`. Ключ идемпотентности запуска сравнивается
только по нему; после старта не меняется никогда.
_Avoid_: Input, payload, request body

**Process data**:
Накопленное состояние процесса: при старте — копия start data, дальше на каждый завершённый
`automatic`-шаг под его собственным step key добавляется результат. Источник `input_mapping`
(TASK.md "Mapping": "source process data pointer") — первый шаг может читать start data через
него ровно потому, что она уже там при создании процесса.
_Avoid_: State, context, variables

### Аренда и разграничение

**Lease**:
Временное право воркера работать над job. Истекает по сроку, heartbeat не предусмотрен.
_Avoid_: Lock, аренда, блокировка

**Lease version**:
Возрастающий счётчик права завершить job. Защищает завершение, а не исполнение.
_Avoid_: Fencing token, версия блокировки

**Execution id**:
Стабильный ключ идемпотентности предметного эффекта, общий для всех попыток одного job.
_Avoid_: Idempotency key, request id, correlation id

**Attempt id**:
Идентификатор конкретной попытки. Не годится как ключ предметного эффекта, потому что меняется
на каждом повторе.
_Avoid_: Run id, execution id

**Reclaim**:
Перехват job после истечения lease: тот же job и тот же execution id, новая попытка и новая
lease version.
_Avoid_: Retry, перезахват, recovery

**Stale finish**:
Попытка завершить job владельцем устаревшей lease. Отклоняется и не меняет ничего.
_Avoid_: Late commit, конфликт, гонка

**Failpoint**:
Именованная граница исполнения, на которой воркер в тестовом профиле объявляет о достижении
и блокируется. Существует для воспроизводимых аварийных сценариев.
_Avoid_: Breakpoint, chaos hook, точка отказа

### Периметр

**Outbox**:
Durable строка намерения доставить внешний запрос, созданная одной транзакцией с самим
запросом до любого сетевого вызова. Отделяет решение отправить от факта отправки:
остановленный `outbox-dispatcher` ничего не теряет, потому что строка уже в базе.
_Avoid_: Очередь, задание на отправку, task

**Inbox**:
Запись о безусловно принятой квитанции, зафиксированная до того, как она применена к
процессу. Отделяет факт приёма от применения: квитанция, пришедшая раньше, чем процесс
дошёл до шага ожидания, не теряется, а ждёт в Inbox. Применение Inbox превращает запись в
workflow-сигнал — то же самое событие, которое сам `apply_signal` уже пишет в историю
процесса, но не совершает предметный эффект (`apply_receipt`, тикет 10) само по себе.
_Avoid_: Очередь входящих, mailbox, буфер

**Receipt**:
Versioned (`v1`), подписанное платформой подтверждение исхода внешнего платежа, полученное
анти-коррупционным слоем из legacy callback провайдера. Не тождественна **Signal**: квитанция
— внешний, подписанный, версионированный документ, хранимый в Inbox отдельно и
идентифицируемый `messageId`; сигнал — внутренний идемпотентный факт, продвигающий конкретный
процесс из `wait_signal`, с собственным `message_id`, производным от `messageId` квитанции.
Одна применённая квитанция даёт ровно один сигнал, но это два разных объекта с двумя разными
пространствами идентификаторов.
_Avoid_: Callback, уведомление, подтверждение платежа

**External request**:
Предметная запись о намерении вызвать провайдера: сумма, валюта, корреляция и
детерминированный от `operationId` идентификатор `externalRequestId`. Не тождественен
**Execution id**: `execution_id` — ключ идемпотентности предметного эффекта job на стороне
платформы, общий для всех попыток одной job; `externalRequestId` — идентификатор,
уходящий наружу к провайдеру и возвращающийся в его callback, детерминированный от
`operationId`, а не от job или attempt.
_Avoid_: Запрос к провайдеру, платёжное поручение, order id

**Decision**:
Предметный факт выбора автоматической или ручной ветки платёжного процесса (лимит, одобрение
оператора, отклонение), сохранённый вместе с событием и следующей job в одной транзакции.
Не тождественно **Event**: событие — append-only строка истории процесса вообще, любого шага;
решение — предметное свидетельство конкретно о выборе ветки, с собственным источником
(автоматический расчёт лимита или конкретный оператор) и причиной, читаемое отдельной
проекцией `decisions`.
_Avoid_: Verdict, вердикт, resolution

**Capability**:
Непредсказуемый сегмент пути внешнего HTTP-callback (`/callbacks/provider-v02/{capability}`),
исполняющий роль секрета маршрута: верный сегмент — необходимое условие того, чтобы запрос
вообще дошёл до анти-коррупционного слоя, неверный отвечает `404` с пустым телом без обратной
связи перебору. Не заменяет подпись — доказывает только то, что вызывающий знал путь.
_Avoid_: Токен, API-ключ, secret path

**Anti-corruption layer**:
Единственное явное место (`receipt-adapter`), где формат провайдера (legacy callback,
`providerPaymentId`/`operationId`/`result`) переводится в формат платформы (подписанная
receipt v1) и подписывается — расхождение форматов исправляется в одной точке, а не
размазывается по ядру. См. [ADR 0005](docs/adr/0005-adapter-signs-exact-bytes.md).
_Avoid_: Транслятор, mapper, integration layer

**Provider payment**:
Платёж, существующий в системе провайдера, идентифицируемый `providerPaymentId`, — сущность
вне платформы, о которой платформа знает только через `External request` (то, что она
запросила) и `Receipt` (то, что провайдер вернул). Платформа не хранит и не вычисляет
состояние платежа провайдера напрямую, только эти две проекции на него.
_Avoid_: Платёж, транзакция провайдера, remote payment

### Наблюдаемость

**Terminal workflow failure**:
Процесс, дошедший до состояния `FAILED`, — окончательный отказ исполнения, зафиксированный в
сохранённом состоянии, а не в памяти процесса. Единица счёта отказов, общая для метрик и для
диагностики, и потому отграниченная от трёх соседей: не попытка (`attempt` со
`status = FAILED` — одна неудачная попытка, за которой может идти успешный retry), не
технический исход доставки (`DEAD` Outbox не проваливает процесс) и не предметный отказ
(`operations.status = REJECTED` — законный исход предметного решения).
_Avoid_: Ошибка, сбой, exception, failed job

**Liveness**:
Способность процесса обслужить probe собственными силами: проба не обращается ни к
PostgreSQL, ни к провайдеру и остаётся успешной, пока процесс жив. Не тождественна
**Readiness**: живость не обещает, что процесс может выполнять работу, — иначе одна
недоступность базы превратилась бы в каскадный рестарт всех зависящих от неё сервисов.
_Avoid_: Health, пинг, доступность

**Readiness**:
Готовность процесса принимать работу: проба подтверждает, что его критическая зависимость
отвечает, и сообщает неготовность, когда нет. У каждого процесса ровно одна критическая
зависимость; провайдер не является ею ни для кого, потому что накопление Outbox — штатный
режим, а не неготовность.
_Avoid_: Health, живость, warm-up
